# CPDC 技术设计

日期：2026-07-20

## 1. 目标与边界

CPDC 是纯 Go、无界面的客户端。它在二层广播网络中完成设备发现、认证、通信包接收、通信包解析和结果确认，并由同一套源码交叉编译出Windows amd64的 `CPDC.exe`以及CCU、MultiBandRadio、MultibandHandheld和HF四个Linux发布文件。

本实现只修改 CPDC 项目。协议口径以本目录的需求文档和 `proto/cpd.proto` 为准。节点广播域被视为可信网络，因此不增加应用层加密和签名。

## 2. 设计原则

- 保持小而直接：只使用 Go 标准库、官方 protobuf 运行时和必要的系统调用支持库。
- 不引入依赖注入框架、消息总线、ORM、插件系统或单实现接口。
- 按稳定职责拆包，避免把网络、协议、文件处理和业务状态写进同一个文件。
- 协议状态由单个事件循环串行修改；耗时解析在可取消任务中运行，完成结果再投递回事件循环。
- 正式文件先在同目录生成并校验，再以单文件替换提交。需求明确要求“先清空再写”的目录不额外实现备份或事务回滚。
- 时间、发送函数和磁盘空间查询通过简单函数参数提供测试接缝，不建立抽象层级。

## 3. 目录结构

```text
cmd/cpdc/                 进程入口、参数和日志初始化
gen/cpd/v1/               protoc 生成的 Go 消息类型
internal/buildinfo/       编译目标标记与工作空间系数
internal/config/          配置读取、校验、ESN、快照原子更新
internal/protocol/        magic 外壳、编解码、消息 ID、时序常量
internal/netio/           网卡选择、UDP 接收、广播与回环双发
internal/client/          会话状态机、认证、传输、解析结果重试
internal/packagezip/      ZIP 目录扫描、安全校验、业务索引
internal/output/          各设备类型产物生成与正式路径提交
internal/fsutil/          原子文件、磁盘空间、目录直接文件清理
scripts/                  可重复的 protobuf 生成与交叉编译脚本
```

## 4. 运行流程

1. 以可执行文件所在目录作为所有相对路径的根目录。
2. 读取并校验 `cpdc_config.json`；ESN 为空时用 `crypto/rand` 生成 16 字节非零数，转换为固定 39 位十进制并立即原子写回。
3. 选择有线业务网卡。未指定 `--interface` 时只允许恰好一个可用的非回环 IPv4；存在多个候选时明确退出并要求运维指定。
4. 在 UDP 39001 端口接收 CPDS 消息。每个合法报文必须满足 4 字节大端 magic `0xEEDDCCBB`、protobuf 可解码、长度不超过 1400 字节且字段校验通过。
5. 所有回复向 `255.255.255.255:39002` 和 `127.0.0.1:39002` 各发送一次。同一个入站报文只驱动一次状态迁移；双发副本不会被转发，因此不会形成循环或广播风暴。
6. 发现回复携带 ESN、进程级 `instance_nonce`、全部设备类型、当前 IPv4 和子网掩码。其他阶段不使用 nonce 去重。
7. AUTH 消息可以分批到达。收齐本实例全部类型且 nodeId 一致后回复一次成功；冲突、缺失或重复绑定通过 `AUTH_RSP` 的枚举结果返回。
8. 新的有效 AUTH 会话终止旧会话的临时工作并进入新会话。已成功或失败的终态实例除新 `DISCOVER_NTY` 外忽略其他消息；解析结果重试期间只额外接收匹配的 ACK。
9. 缓存命中只跳过文件传输，不跳过解析。命中条件为缓存实际文件的文件名和重新计算的 SHA-256 都与 `TRANSFER_START_NTY` 一致。
10. 传输使用 1200 字节、0 起始分包。落盘使用 `WriteAt` 和位图；END 到达时合并缺包区间并按单报文上限拆分 `TRANSFER_LOSSPACK_REQ`。完整后校验文件长度和 SHA-256，再进入解析。
11. 解析先执行 ZIP 防御性校验，再按 `deviceTypes` 配置顺序生成所有临时产物。每种类型成功后提交正式文件；前一类型失败时后续类型记为 skipped。所有类型成功后更新本地快照并发送 `PARSE_COMPLETE_REQ`。
12. 本地解析结果在发出首个完成请求时即生效；未收到 ACK 时使用同一 message_id 和内容每秒重发，最多五次。

## 5. 状态机

主要状态为 `idle`、`discovered`、`authenticated`、`receiving`、`parsing`、`reporting`、`terminal`。

- `DISCOVER_NTY` 始终可开始下一轮发现，并清理已结束会话的内存状态。
- 发现和认证失败不会保留临时文件或更新快照。
- 传输或解析中个别设备掉线由 CPDS 汇总处理；本 CPDC 继续完成自身流程。
- 解析任务有 30 秒硬截止时间。超时通过 `PARSE_COMPLETE_REQ(result=failed)` 上报。
- CPDS 断电时，接收会话空闲 30 秒后关闭临时文件并删除本会话单个临时文件；已校验缓存和已提交正式产物不受影响。
- 终态只等待下一次发现，避免旧会话消息重新打开已结束流程。

## 6. 文件与空间安全

在写入前读取 ZIP 中央目录，计算展开大小和工作空间，检查条目数量、压缩比、单文件大小、路径、类型、重复路径、Windows 保留名、业务目录、JSON 及引用完整性。解压或复制时重新累计实际写入量并读取到 EOF，使伪造的目录元数据、CRC 错误和大小溢出无法绕过校验。

所需空间覆盖原始包、展开内容、全部暂存输出和 20% 余量；CCU 构建使用 2 倍工作空间系数。空间不足在传输完成结果中使用枚举错误码返回。

## 7. 产物策略

- MultiBandRadio / MultibandHandheld：生成 `plan_local.tar`、普通 tar 内容但文件名为 `mission.tar.gz`，并更新或创建 `ReReadJson.ini`。
- HF / SmallHandheld：生成 `plan_local.tar`，仅确保 `ReReadVal=1`。
- CCU：清空 `./txbz_ccu` 下的直接普通文件，复制当前 CCU 配置为原文件名。
- Server / IEC：清空 `./txbz_server` 下的直接普通文件，把原包业务根加入/替换 `local_node.json` 后以原包名写入。
- 原始已验证通信包只在 `./txbz` 保留一份。

## 8. 测试策略

- 单元测试覆盖配置、ESN、协议外壳、网卡筛选、认证聚合、分包位图、缺包区间、ZIP 攻击面、业务引用、各类型产物与快照。
- 状态机测试使用可控时间和内存发送器，验证超时、重试、终态忽略和新会话抢占。
- 集成测试在本机 UDP 回环上覆盖发现到解析完成的最小闭环。
- 最终执行 `go test ./...`、`go vet ./...`、四个目标的交叉编译和需求关键字一致性检查。

## 9. 已接受的实现取舍

- “有线网卡”无法仅靠跨平台 Go API 稳定识别物理介质；实现以可用非回环 IPv4 为候选，生产环境多网卡时必须使用 `--interface` 消除歧义。
- 同机广播与回环双发可能使接收端看到两个相同 message_id；状态机按消息语义做幂等处理，但不额外维护全局 message_id 去重表。
- `mission.tar.gz` 严格按需求输出未 gzip 的 tar 数据，只保留该文件名。
