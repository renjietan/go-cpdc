# CPDC 构建文件存储目录设计

## 目标

在仓库根目录新增统一的 `build/` 构建存储目录，将构建脚本、编译器、应用程序、安装脚本和配置文件按用途分开。现有根目录下的旧路径暂时保留，由用户后续手动删除。

## 目录结构

```text
build/
├── scripts/          编译及代码生成脚本
├── compiler/         Go 编译器、压缩包及展开后的本地工具链
└── dist/
    ├── bin/          构建生成的应用程序
    ├── install/      自启动脚本（本次仅创建 .gitkeep）
    └── config/       发布配置文件
```

## 迁移规则

- 复制现有 `scripts/` 内容到 `build/scripts/`，并将新目录中的脚本改为以仓库根目录为基准定位源码，以 `build/compiler/` 为本地工具链目录，以 `build/dist/bin/` 为默认输出目录。
- 复制现有 `compiler/` 内容到 `build/compiler/`，保证旧目录删除后专用构建仍可独立工作。
- 将现有 `dist/` 中的 CPDC 应用程序复制到 `build/dist/bin/`。
- 将现有 `dist/` 中的 `cpdc_config*.json` 和 `ReReadJson.ini` 复制到 `build/dist/config/`。
- 现有 `dist/` 中的 `txbz*`、任务包及其他运行数据不复制到新构建目录。
- 根目录的 `cpdc_config.demo.json` 是源码示例，保持原位。
- 旧 `scripts/`、`compiler/`、`dist/` 以及其中的文件均不删除、不移动，也不作为后续维护入口。

## 引用更新

- README 中的构建命令和输出说明改为新路径。
- 构建测试改为调用 `build/scripts/` 中的脚本并验证 `build/dist/bin/` 产物。
- `.gitignore` 改为忽略新目录中展开的编译器和生成产物，同时暂时保留旧路径的忽略规则。
- 当前有效需求文档中的构建脚本路径改为新路径；按项目约束，同步更新 CPDS 项目中的对应需求文档。
- 历史设计和实施计划记录原发生时的路径，不回写修改。

## 兼容与错误处理

新脚本必须从自身位置正确推导仓库根目录，不能依赖调用者当前工作目录。缺少编译器压缩包、工具链版本不符或输出目录无法创建时，继续明确报错。旧脚本只作为临时副本保留，不承诺与新脚本同步。

## 验证

- 运行受影响的 PowerShell 构建测试，确认其使用新脚本、新编译器路径和新输出目录。
- 运行 Go 测试与静态检查。
- 运行统一构建脚本，确认全部常规目标生成到 `build/dist/bin/`。
- 检查 `build/dist/config/` 仅包含发布配置，`build/dist/install/` 为空目录占位，且运行数据仍只留在旧 `dist/`。
- 检查 CPDC 与 CPDS 的对应需求文档一致。
