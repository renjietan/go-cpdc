# CPDC 解析结果持久化设计

## 问题

CPDC 解析过程中会对临时文件执行 `File.Sync`，但解析成功快照写入完成后立即上报成功。Linux 设备如果随后立即重启或掉电，内核中尚未提交到稳定存储的文件系统数据和目录元数据可能丢失。

## 设计

在 `Parser` 串行解析流程中增加一个平台持久化屏障。全部正式输出和成功快照写入完成后、返回成功结果前，Linux 实现调用 `unix.Sync()`；非 Linux 实现为空操作，以保持现有 Windows 构建兼容性。直接调用系统调用，不启动外部 `sync` 进程。

持久化函数作为 `Parser` 的私有依赖保存，由 `NewParser` 设置生产实现。测试替换该依赖，以验证屏障只在完整成功路径执行，而且执行时正式输出和成功快照已经可见。

## 错误和时序

Linux `sync(2)` 没有可返回的逐文件错误，因此解析结果错误码不变。调用是同步阻塞的：在持久化屏障返回前，CPDC 不得生成成功的 `ParseOutcome`，也就不会向 CPDS 发送成功的 `PARSE_COMPLETE_REQ`。

## 验证

- 单元测试验证持久化屏障在输出和快照之后执行。
- 运行 CPDC 全部 Go 测试。
- 交叉编译 Linux 和 Windows 目标，验证平台文件选择和依赖兼容性。
